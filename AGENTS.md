# AGENTS.md

Instructions for coding agents working in this repository. Humans may find it
useful too, but [`README.md`](README.md) is the friendlier entry point and
[`docs/`](docs/README.md) holds the reasoning.

Each app has its own `AGENTS.md` with rules that apply only there. Read the one
for the surface you are touching:

- [`apps/web/AGENTS.md`](apps/web/AGENTS.md)
- [`apps/mobile/AGENTS.md`](apps/mobile/AGENTS.md)
- [`apps/theme/AGENTS.md`](apps/theme/AGENTS.md)

## What this project is

One Shopify store rendered three ways — a Next.js app, an Expo app, and a Liquid
theme — over a shared Storefront client and one set of design tokens. See
[`docs/architecture.md`](docs/architecture.md).

## Before you change anything

**This repository is public.** No token, password or store credential may be
committed, in any file, on any branch. Secrets live in gitignored `.env.local`
files. If you need a credential to verify something, ask; do not invent a
placeholder that looks real.

**Do not change a version pin without reading why it exists.** Several are
load-bearing and look like neglect from the outside. They are recorded in
[`docs/adr/`](docs/adr/README.md), and the two that bite hardest are:

- [`lightningcss` is pinned to 1.30.1](docs/adr/0004-pin-lightningcss-to-1-30-1.md).
  Newer versions fail **at Metro bundle time only** — install, typecheck and CI
  all pass first.
- [TypeScript is `~6.0.3`, not 7](docs/adr/0002-typescript-6-over-7.md). No
  `typescript-eslint` release supports 7.

## Verification

`turbo lint typecheck build` is the bar, and CI runs it on every pull request
across every package.

```bash
pnpm install
pnpm turbo lint typecheck build
```

**Passing locally proves nothing if the thing making it pass lives outside the
repository.** This has already broken CI twice:

- `expo-env.d.ts` is generated by Expo and gitignored, so a fresh clone lacks a
  type declaration that exists on a machine which has run `expo start`.
- `@shopify/cli` existed only as a global Homebrew install, so a clean runner had
  no `shopify` binary for `theme check`.

When a fix depends on a generated or globally installed file, check whether a
fresh clone would still have it.

**Verify claims about rendered output by looking at rendered output.** A gallery
bug shipped with an entirely correct DOM — right elements, right ARIA, right
positions — and was invisible until someone looked at the pixels. "The markup is
correct" is not the same statement as "it works".

## Conventions

These come from the user's global preferences and are consistent throughout the
codebase. Match them.

|            |                                                                                         |
| ---------- | --------------------------------------------------------------------------------------- |
| Language   | TypeScript. `any` is not acceptable                                                     |
| Spelling   | **British English**, in code comments and prose alike                                   |
| Components | `const` arrow functions, never `function` declarations, never classes                   |
| Exports    | **Named exports**, including default-exported route files: `export { Page as default }` |
| Types      | `interface` for object shapes, `type` for unions and aliases                            |
| Async      | `async`/`await`, not promise chains                                                     |
| Files      | kebab-case. React components PascalCase _inside_ the file                               |
| Imports    | Absolute with path aliases where configured                                             |
| Errors     | **Explicit error types over generic catches** — see `packages/shopify/src/errors.ts`    |
| Formatting | Prettier: double quotes, semicolons, trailing commas, 90 columns                        |

`tsconfig` is strict, with `noUncheckedIndexedAccess`, `noImplicitOverride`,
`noUnusedLocals`, `noUnusedParameters` and `verbatimModuleSyntax` all on. That
last one is why codegen runs with `useTypeImports: true` — the generator was
fixed rather than the compiler loosened, and that is the preferred direction
whenever the choice comes up.

Always consider accessibility (WCAG 2.1 AA), mobile responsiveness, and loading
and error states. Flag security concerns with ⚠️.

## Comments

Comments explain **why**, not what. The codebase is dense with them because most
non-obvious lines here exist to work around something real, and a comment naming
the failure is what stops it being removed.

Keep that standard. A comment restating the code is worse than none.

## The shared package rule

**`packages/shopify` must stay platform-neutral.** Both React surfaces import it.
Bare `fetch`, no DOM, no React Native, no React. Platform-specific ergonomics
belong in the app.

TanStack Query wrappers live in `apps/mobile` for exactly this reason — the web
app fetches in Server Components and would never call them.

After editing `packages/shopify/src/queries.ts`, run `pnpm codegen` and commit
the result. **CI fails if the generated output has drifted.**

After editing `packages/tokens/src/tokens.ts`, run
`pnpm --filter @formulate/tokens build`, then
`pnpm --filter @formulate/theme build` to copy the result into the theme. Never
hand-edit `theme.css`, `tokens.css`, or `apps/theme/assets/tokens.css`.

## Git

- Branch from `main`; never commit to it directly. Branch protection enforces
  this, with linear history and required up-to-date status checks.
- Commit incrementally as work lands. Do not batch a day of work into one commit
  and reconstruct the history afterwards.
- Commit messages explain **why**, at length where the reason is not obvious.
  Read the existing log before writing one — the standard there is the standard.
- Only commit or push when asked.

## Decision records

When you make a decision that would look arbitrary to someone encountering it
later, write an ADR **in the same pull request** as the change. Copy
[`docs/adr/0000-template.md`](docs/adr/0000-template.md) and take the next
number.

The test: _would someone reasonably assume this was a mistake?_ If yes, write it
down.
