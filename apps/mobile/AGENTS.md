# AGENTS.md — apps/mobile

Rules specific to the Expo app. The root [`AGENTS.md`](../../AGENTS.md) applies as
well; this file only records what is different here.

Background: [`docs/surface-mobile.md`](../../docs/surface-mobile.md).

## The Expo Go ceiling

`@shopify/checkout-sheet-kit` is a **native module**. Anything that touches
checkout requires a **development build** — Expo Go cannot load it.

Autolinking picks the module up through `expo prebuild`; no config plugin is
needed. iOS builds need CocoaPods installed locally, because `pod install` links
what autolinking discovered.

`ios/` and `android/` are gitignored. They are **generated**, not source. Never
edit them expecting the change to persist, and never commit them —
`app.config.ts` is the source of truth for native configuration.

## Do not touch these three files casually

**`nativewind-env.d.ts`** carries `/// <reference types="expo/types" />` alongside
the NativeWind reference. That line looks redundant because `expo-env.d.ts`
declares the same thing — but `expo-env.d.ts` is generated by Expo and gitignored
by Expo's own template, so a fresh clone does not have it and typecheck fails on
`global.css`. This already broke CI once. Leave it.

**`metro.config.js`** wraps the Expo default with `withNativewind` and does
nothing else. Do not add `watchFolders`, `resolver.nodeModulesPaths` or
`resolver.disableHierarchicalLookup`. Expo SDK 52+ detects the monorepo itself,
and setting those manually now _causes_ resolution bugs rather than fixing them.
Most monorepo guidance online predates this and is actively wrong.

**`.npmrc`** at the repository root sets `node-linker=hoisted`. Metro and
autolinking both need a flat, real-directory `node_modules`. Removing it breaks
the app and nothing else.

## Version pins

⚠️ `lightningcss` is pinned to **1.30.1** in `pnpm-workspace.yaml`. NativeWind v5
deserialises its output inside `react-native-css`, and any newer version fails
**at Metro bundle time only** — install succeeds, typecheck passes, and the error
names deserialisation rather than versions. See
[ADR 0004](../../docs/adr/0004-pin-lightningcss-to-1-30-1.md).

NativeWind is pinned exactly at `5.0.0-preview.4`, no range, because preview
releases can break between versions —
[ADR 0003](../../docs/adr/0003-nativewind-v5-and-tailwind-v4.md).

React is pinned to `19.2.3` workspace-wide. Under the hoisted node linker a
second React copy would break hooks here.

## Environment variables

```
EXPO_PUBLIC_SHOPIFY_STORE_DOMAIN
EXPO_PUBLIC_SHOPIFY_STOREFRONT_TOKEN
EXPO_PUBLIC_SHOPIFY_API_VERSION
```

The `EXPO_PUBLIC_` prefix is **required**, not a stylistic choice: Metro inlines
these at bundle time and the bundle _is_ the client. A public Storefront access
token is designed for this — scoped to storefront reads, rate limited per buyer
IP.

⚠️ There is no server here to hide anything behind. An Admin API token, a
Recharge key or any private credential in this app ships to every device. If a
feature needs one, it needs a backend, and that conversation happens before the
code.

`app.config.ts` exists rather than `app.json` so EAS can inject these at build
time; a static JSON file cannot read the environment.

## Data access

`lib/queries.ts` wraps the shared client in TanStack Query. Add new queries here,
not in `packages/shopify` — the web app fetches in Server Components and would
never call them.

`request()` returns a Result rather than throwing, so query functions convert a
failed Result into a thrown `Error`. That is the contract TanStack needs to drive
`isError`; keep it.

Every screen needs a loading state (`isPending`) and an error state (`isError`).
Both existing screens have them; match that.

## Styling

NativeWind v5 with the same `@formulate/tokens/theme.css` the web app uses.

`components/site-footer.tsx` assumes a parent scroll container with `p-4`, and
cancels it with `-mx-4` so its top border reaches the screen edges. That coupling
is why it is a shared component with a documented assumption rather than markup
duplicated in two screens. If you use it somewhere with different padding, fix
the assumption rather than the symptom.

Style props that Tailwind cannot express — `aspectRatio`, `borderRadius` on
`expo-image` — use inline `style`, which is correct and not a smell.

## Verification

Screens are verified on an **iPhone 17 Pro simulator**. "It typechecks" is not
verification for anything visual.

`pnpm --filter @formulate/mobile build` runs `expo export`, which bundles through
Metro — so it is the check that would catch a bad `lightningcss`.
